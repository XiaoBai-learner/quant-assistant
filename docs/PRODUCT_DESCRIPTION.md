# Quant Assistant 产品功能描述

## 1. 产品定位

Quant Assistant 是一个面向个人量化研究的 Python 工具包，目标是帮助使用者完成从数据获取、因子计算、策略构建到回测验证的闭环。当前版本更适合作为本地研究框架和策略实验台，而不是实盘交易系统或多人协作平台。

项目当前聚焦 A 股研究场景，支持多数据源接入、技术指标计算、策略信号生成、事件驱动/向量化回测、基础风控、机器学习预测和终端图表展示。

## 2. 目标用户

- 个人投资者：希望用代码验证交易想法、复盘策略表现。
- 量化学习者：需要一个模块完整、便于阅读和扩展的练习项目。
- 策略研究者：需要快速拉取行情、计算因子、组合信号并做初步回测。
- 开发者：希望基于现有框架继续扩展数据源、回测细节、风控或实盘接口。

## 3. 当前产品边界

### 已支持

- 多数据源：AKShare、EFinance、TickFlow，以及统一数据获取器。
- 数据管理：MySQL 存储、统一查询、数据校验、缓存基础设施。
- 因子计算：常用技术指标和独立因子引擎。
- 策略研究：策略基类、信号合成、股票筛选、内置策略、组合策略和参数优化。
- 回测验证：事件驱动回测、向量化回测、模拟券商、真实撮合、组合净值和绩效指标。
- 机器学习：特征工程、模型封装、评估和预测器基础能力。
- 可视化：终端 ASCII K 线、指标和表格渲染。
- 风控基础：仓位、回撤、集中度等规则管理。
- 命令行：`quant` / `qa` 命令入口，覆盖数据、因子、回测、机器学习和版本查询。

### 暂不支持

- 实盘交易：没有券商网关、账户同步、订单状态机和自动执行能力。
- 生产监控：没有实时告警、健康检查面板和链路追踪。
- Web 平台：没有浏览器端策略工作台、看板和多用户权限。
- 分布式能力：没有任务队列、分布式回测和远程执行调度。
- 投资建议：项目只提供研究工具，不输出任何确定性投资结论。

## 4. 核心功能描述

### 4.1 数据管理

数据层负责行情和基础数据的获取、清洗、校验、存储和查询。当前数据源覆盖 AKShare、EFinance 和 TickFlow，并提供 `UnifiedDataFetcher` 作为统一入口。持久化层以 MySQL 为主，适合保存股票基础信息、日线行情、财务指标、交易日历和更新日志。

下一步需要重点收敛不同 fetcher 的方法命名、字段格式、日期格式和异常语义，避免上层策略或回测因为数据源差异产生隐性错误。

### 4.2 因子与指标

因子层提供常见技术指标和可扩展的因子引擎。当前包含移动平均、指数移动平均、MACD、RSI、布林带、KDJ、ATR、OBV 等指标，同时存在 `quant_assistant/factors` 和 `quant_assistant/strategy/factors` 两套相关实现。

下一步需要明确两套因子模块的职责边界：一套作为通用因子计算引擎，一套作为策略层内部依赖，或将二者合并成统一因子服务。

### 4.3 策略研究

策略层通过 `BaseStrategy` 定义策略生命周期，通过 `Signal`、`SignalGenerator`、`StockSelector`、`StrategyBuilder`、`StrategyOptimizer` 等组件支持从规则到信号再到优化的研究流程。当前适合开发单标的或多标的规则策略，并支持基础参数搜索和遗传算法优化。

下一步需要补齐策略示例、策略配置格式和策略运行结果的标准输出，降低新策略接入成本。

### 4.4 回测验证

回测层提供事件驱动和向量化两种模式，包含模拟券商、真实撮合、投资组合、交易成本、绩效分析和回测可视化。当前已经具备策略验证主流程。

下一步需要增强可信度：交易日历、停牌、涨跌停、成交量约束、滑点模型、基准收益和回测结果可重复性应成为重点。

### 4.5 机器学习

机器学习模块提供特征工程、模型训练、模型评估和预测器基础能力。当前更像研究辅助能力，适合为策略提供额外信号或预测参考。

下一步需要明确训练数据切分、特征泄漏检查、模型保存路径、评估指标和预测结果格式。

### 4.6 可视化与 CLI

可视化层主要服务终端使用场景，提供 ASCII K 线、技术指标和表格渲染。CLI 通过 `quant` 和 `qa` 命令暴露数据、因子、回测和 ML 功能。

下一步需要修正 CLI 示例与实际 API 的差异，并为常用命令增加端到端测试。

## 5. 当前技术状态

| 领域 | 状态 | 风险 |
|---|---:|---|
| 包结构 | 可用 | `__init__.py` 导出中仍有历史类名，可能与实际实现不一致。 |
| 文档 | 已整理入口 | 主要文档入口已统一，后续需持续校准示例与真实 API。 |
| 数据源 | 可用 | 高层 API 已增加统一获取器、字段标准化和日期裁剪；底层数据源 schema 仍需继续收敛。 |
| 回测 | 可用 | 市场微结构约束和真实交易限制仍需增强。 |
| 测试 | 待加强 | 当前仓库未看到完整 tests 目录，回归验证不足。 |
| 实盘 | 未开始 | 需要先完成模拟交易与风控闭环，再考虑真实券商接口。 |

## 6. 下一轮开发任务建议

### P0：项目一致性修复

1. 修正 `quant_assistant/__init__.py` 的导出清单，保证导出的类、函数与实际模块一致。
2. 持续检查文档示例，保证导入路径、方法名和真实 API 一致。
3. 扩展最小测试套件，当前已覆盖策略创建、数据 API 注入、通用查询、基础回测和统一获取器 fallback。
4. 继续梳理 `QuantAPI` 与底层 fetcher 的方法名差异，尤其是分钟、实时和财务数据接口。

### P1：数据层标准化

1. 定义标准行情字段：`symbol`、`trade_date`、`open`、`high`、`low`、`close`、`volume`、`amount`。
2. 为 AKShare、EFinance、TickFlow 增加统一适配层和字段映射测试。
3. 明确日线、分钟线、实时行情、财务数据的返回 schema。
4. 补充数据源失败时的异常类型、日志和 fallback 规则。

### P1：回测可信度增强

1. 接入交易日历，避免非交易日推进。
2. 增加停牌、涨跌停和成交量约束。
3. 完善手续费、印花税、滑点和冲击成本模型。
4. 增加基准收益、超额收益、净值曲线和交易明细导出。

### P2：策略开发体验

1. 提供标准策略模板和 2-3 个可运行示例。
2. 统一策略参数配置和结果输出格式。
3. 增加策略信号质量评估和回测前数据检查。
4. 整理 `strategy/factors` 与顶层 `factors` 的职责边界。

### P2：产品化准备

1. 增加 `examples/` 目录，提供完整研究流程脚本。
2. 增加开发者指南，说明模块边界、测试方式和扩展数据源方式。
3. 在 CLI 中增加 `doctor` 命令，检查依赖、数据库和数据源可用性。
4. 规划模拟交易层，为未来实盘交易做前置抽象。

## 7. 成功标准

下一轮开发完成后，项目应达到以下状态：

- 新用户可以在 15 分钟内完成安装、获取一只股票数据、计算指标并跑通回测。
- 所有 README 示例可以直接运行或明确标注前置条件。
- 数据源返回字段稳定，上层策略不依赖具体数据源差异。
- 核心 API、CLI 和至少一个策略回测流程有自动化测试覆盖。
- 文档清晰标注“已实现”和“规划中”，避免误导使用者认为已支持实盘交易。
